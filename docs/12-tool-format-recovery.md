# Tool format recovery — 0.4.4

Задачи 36–38 в установленной 0.4.3 завершились без вызовов tools. Модель вывела
`<call:list_dir{path:<|"|>.<|"|>}/>` как content; сервер не вернул tool_calls.
Предыдущий web-тест проверял конкретные исправления, но не этот отказ на общем запросе.

Gemma-профиль распознаёт попытку вызова в конце ответа без tool_calls и делает
до двух повторных запросов с объяснением, что вызов не исполнен, и правильным
нативным форматом. Текст не интерпретируется как команда. Исполняются только
структурированные tool_calls через существующий dispatch и подтверждения.
После трёх неудачных ответов возвращается ошибка. Теги в цитатах обычного текста
не запускают восстановление. Исторические ответы с таким хвостом исключаются
из контекста, чтобы не закреплять неправильный формат. Сохранённые сообщения
не удаляются. Запрос «Давай улучшим наше веб приложение» распознаётся как действие.

Регрессия: модель сначала возвращает сырой тег, после коррекции читает и меняет
реальный файл. Вторая модель никогда не исправляет формат: файл неизменён,
показана ошибка. Live smoke: три свежие копии текущего пользовательского проекта,
в истории прежний сырой тег, запрос «да делай всё по порядку», read_only=true.
Все три начали настоящий list_dir. После первого успешного observation тест
отменяет ход: он проверяет начало работы, а не качество дальнейших улучшений.

Формат сверён с [Gemma 4 parser установленного llama.cpp](https://github.com/ggml-org/llama.cpp/blob/d81235049/common/parsers/gemma4.cpp).
