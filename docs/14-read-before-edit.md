# Read before edit — 0.4.7

Модель передаёт `edit_file(path, start_line, end_line, text)`. Диапазон включительный,
нумерация с 1. Старый исходный фрагмент больше не требуется копировать в аргументы.

Воркер хранит снимок файла и множество полностью прочитанных строк только в пределах
текущего хода. Успешный `read_file` или `quote_file` разрешает редактировать только
строки, полностью попавшие в ответ модели. Непрочитанные промежутки, обрезанные строки,
чтение в прошлом ходе и выдуманные координаты разрешения не дают.

`edit_file` проверяет весь снимок файла перед записью. Внешнее изменение, даже за
пределами выбранного диапазона, требует нового чтения. После успешной записи
разрешения сбрасываются; следующая правка требует нового чтения. `append_file`
тоже требует свежего чтения конца файла. Проверка снимка повторяется внутри функции
редактирования перед подготовкой нового содержимого. Это обнаружение устаревшего
снимка, а не блокировка внешних редакторов на уровне файловой системы.

Старые search/old_text вызовы принимаются лишь при уникальном точном совпадении внутри
свежепрочитанных строк. Прямые функции инструментов остаются доступными для внутренних
проверок; модель получает доступ к записи через обязательный guard в `run_turn`.
Права на shell/удаление/архивы не меняются. Новые файлы создаются отдельным create_file,
который не перезаписывает существующие. Нужность и качество нового кода проверяется
отдельно: чтение защищает координаты и исходное состояние, но не гарантирует логику.

Перезапись существующего файла через copy_file/move_file/restore_file требует чтения
всего файла назначения. Старый write_file с append проходит тот же guard конца файла.
