# Runtime quality — 0.4.3

Реальный ход 11 в установленной версии обнаружил копирование `N|` из read_file в JavaScript, повторные записи HTML без изменений и частое сжатие контекста при окне 8096. Эти отказы не воспроизводились прежними простыми тестами.

Исправления:

- edit/create/append отклоняют последовательные префиксы строк в исходном коде до записи. Номера не удаляются автоматически; обычные текстовые данные поддерживаются.
- Замена на тот же текст возвращает NO_CHANGE и не считается успешной правкой; backup не создаётся.
- bubblewrap монтирует /tmp до workdir, сохраняет доступ к рабочей папке и создаёт пути /bin, /lib, /lib64.
- shell RLIMIT_AS увеличен с 512 MiB до 4 GiB: это лимит виртуальных адресов, Node/V8 требует адресного пространства даже для минимального запуска. CPU, размер файлов, timeout и изоляция сети сохранены.
- Gemma sampling и reasoning: см. docs/02-gemma4-chat-template.md. stack2.yml: context 64000, batch 2048, ubatch 512, reasoning 2048; параметры ключей и доступа не менялись.
- Перед каждым запросом выполняется полный fit_budget, а не один проход сжатия. Большой первый ответ инструмента также ограничивается; связь вызова с результатом сохраняется.

Проверка: 17 offline CTest + laws + strict qmllint. Live web acceptance включает три повтора на свежих папках с одинаковыми тремя ошибками: порядок инициализации FS, передача Kernel в AppManager, неправильное сложение. Проверяется фактический запуск Node, сохранность API и неизменность HTML/CSS/тестового файла; максимум 20 вызовов и 6 записей. Интерпретатор копируется в временную папку теста, production workdir не используется.

Прогон через loopback proxy фиксирует seed=42 для воспроизводимого сравнения. Новый профиль прошёл 3/3: 10/11/10 вызовов, 2/3/2 записи; 23/58/53 секунды. Это проверка данного сценария, а не гарантия качества произвольных задач. Исходный пользовательский проект сохранён в /tmp/arli-actual-project; автоматически не откатывался.

После коррекции текущего stack2.yml повторный прямой прогон без proxy/фиксированного seed прошёл 3/3: 14/9/11 вызовов, по 2 записи, 69/32/48 секунд. Серверное окно 64000, клиентское 49152. Ошибки отдельных tools не скрываются: см. web-agent-eval-current.json; все три сценария восстановились и прошли runtime-проверку. Создание, открытие и удаление собственного пустого диагностического чата проверено через установленный сервис. Настройки изменены штатным SetSettings, ключ не прочитан и не заменён.
