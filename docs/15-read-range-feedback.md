# Read range feedback — 0.4.8

Установленная 0.4.7, задача 57: модель трижды пыталась заменить script.js 1–542,
прочитав только 1–400. Запрос read_file(end_line=542) ограничивался 400 строками.
Общая READ_REQUIRED не называла пропущенный хвост; модель повторяла начало.
После чтения 401–542 запись прошла, но только после четырёх отказов и 19 вызовов.

Теперь отказ сообщает первый непрочитанный непрерывный диапазон (до 400 строк)
и точные JSON-аргументы read_file. Он явно запрещает повторять начало. Ограниченный
read_file также сообщает, что запрошенный конец не показан и оставшиеся строки
не считаются прочитанными. Изменённый снимок и неверные координаты получают
отдельные причины отказа. Обязательное чтение не ослаблено.

Регрессия воспроизводит 542 строки: read_file(1,542) показывает 1–400, edit_file(1,542)
отклоняется с read_file(401,542); после чтения хвоста запись проходит. Это исправляет
подсказки восстановления после ошибки, а не гарантирует качество нового кода модели.

## Аудит файловых инструментов, 2026-10-10

Дополнительно исправлены воспроизводимые дефекты исполнения:

- `read_file` раньше обрезал исходный файл до 120000 байт **до** выбора строк.
  Хвост больших файлов становился недоступен, а `lines` сообщал неверный размер.
  Теперь лимит применяется к выдаваемому диапазону, полные строки не разрезаются,
  продолжение указывает следующий диапазон. Слишком длинная отдельная строка
  возвращает `LINE_TOO_LONG`, а не мнимое успешное чтение.
- Замена диапазона пересобирала весь файл, меняя CRLF, неразрывные пробелы и
  завершающий перевод строки. Теперь меняются только байты выбранного диапазона;
  поиск фрагмента также переводит координаты обратно в исходные байты.
  Нормализация не заменяет NBSP внутри исходного кода или строковых литералов.
- Нестрогое построчное совпадение захватывало разделитель, но замена без `\n`
  склеивалась со следующей строкой. Разделитель теперь сохраняется.
- Пустой существующий файл нельзя было ни прочитать, ни заполнить. Успешное
  чтение пустого файла теперь разрешает `append_file`; без чтения запись запрещена.
- Предсказуемый `.arli-tmp` заменён приватным эксклюзивным временным файлом.
  Запись проверяет завершение и синхронизацию, сохраняет обычные права доступа
  и исполняемые биты существующего файла. Создание публикуется без перезаписи
  файла, который мог появиться параллельно. Setuid/setgid не переносятся.
- После восстановления пропущенного `path` цикл использовал старые аргументы
  для учёта проверки и инвалидирования. Теперь исполнение и учёт используют
  один восстановленный набор аргументов; отклонённый синтаксис не теряется.

Регрессии: `file-edit-integrity`, сценарий `syntax_inferred` в `turn-execution`.
Реальная модель: дополнительный сценарий `file_integrity` в `arli-live-eval`
проверяет правку строки 1501 после 120 KB, сохранность CRLF/NBSP/EOF и заполнение
пустого файла. Все задания выполняются в отдельных временных каталогах.

Границы: синтаксическая проверка не доказывает корректность поведения; нет
гарантии решения произвольной задачи моделью. Проверка снимка перед записью
не является блокировкой для внешнего редактора. Сохранение ACL/xattr/владельца
при замене inode не реализовано. Строка, превышающая бюджет чтения, пока требует
другого способа работы; инструмент явно сообщает об этом.

Также исправлен сам `mutation-diff` тест: раньше `return false` из `main`
маскировал провал как exit code 0, а ожидаемый diff относился к другому пути.
Теперь несовпадение завершает тест ошибкой, проверяется diff нужного файла.

Результат реальной Gemma 4 26B: **5/5** сценариев прошли, включая 16 правок
с 17 сжатиями контекста и `file_integrity` (6 tools, 2 записи, 0 ошибок).
Единственная ошибка инструмента в полном прогоне — ожидаемое чтение отсутствующего
файла в `recovery`; задача после неё успешно завершена. Машиночитаемый отчёт:
