# Edit coordinates — 0.4.6

В задаче 40 новая модель дошла до edit_file, но дважды передала start_line/end_line
и 17 KB текста без path; затем path/end_line и текст без start_line. Ошибки записи
не связаны с правами на файл. Последующая попытка delete_file была отклонена пользователем.

В схеме модели edit_file теперь явно требует path/search/text: один уникальный
исходный фрагмент и его замену. Поле text находится после адреса и исходного фрагмента.
Диспетчер также принимает прежние new_text/old_text и их aliases. Координаты не
угадываются по end_line: неоднозначный вызов по-прежнему не меняет файл.
Промпт рекомендует локальные правки вместо ненужного полного переписывания.

Промежуточный line-based прогон на копии реального 539-строчного script.js записал
шесть правок, но синтаксическая проверка не прошла: номера после вставок устаревали.
Прогон только с search тоже не прошёл: нативные Gemma-аргументы теряли обязательные
поля и содержали некорректные имена вроде end_line=275. Простая смена схемы не
обеспечила соблюдения этой схемы нативным парсером.

Gemma-профиль теперь использует response_format=json_schema: выбор tool/final,
имя инструмента из каталога и его params ограничены грамматикой. Адаптер проверяет
имя, обязательные поля и типы, затем преобразует JSON в прежний tool_calls.
Все разрешения и dispatch сохраняются; текст не исполняется. JSON управления не
стримится в чат, размышления стримятся. Generic-профиль не меняется.
История инструментов по-прежнему передаётся через канонический Gemma template.

Чтение исходников использует лимит, соответствующий окну контекста: 6000–48000
символов на ответ. Раньше даже в окне 49152 середина 200–400 строк обрезалась
фиксированными 6000 символами, мешая модели выбирать существующие фрагменты.

Регрессия записывает точный текст 539-строчного файла и проверяет backup.
Аудит обрезает UTF-8 на границе символа: в той же задаче срез в середине эмодзи
ломал JSON и не позволял сохранить событие аудита.

Известная проверка (`node --check`, тесты, сборка и другие поддержанные команды)
повторяется после успешной записи через обычный run_shell с прежними разрешениями.
Проваленная или устаревшая проверка блокирует успешный итог; отказ пользователя
не обходится. JSON итогового ответа не выводится до этой проверки.

Полный CI: 17/17, arli-law, qmllint, module size law. Это проверка механики
агента, а не доказательство качества любой правки Gemma. Прогон на копии реального
539-строчного script.js при temperature=1 записал 5 изменений, но синтаксис не
исправил (31 вызов, 9 ошибок инструментов). Исходный проект не изменялся.

Контрольный прогон temperature=0.2/seed=42 с повторной проверкой после записи
тоже не исправил большой файл: 6 записей, 21 вызов, 8 ошибок инструментов,
осталась SyntaxError. Поэтому снижение температуры в продукт не перенесено.
В этом прогоне обнаружилась вставка `<tool_call|><|channel>` в JavaScript;
такая служебная последовательность теперь отклоняется до backup и записи.
