# Ключи и токены

Арли не выдаёт ключ языковой модели.

## Модель

Локальный сервер вроде llama.cpp на `http://127.0.0.1:8080/v1` ключа не требует. Пустое поле и чип «ключа нет» для него нормальны.

Ключ нужен только чужому OpenAI-совместимому адресу. Его вводят в настройках («Записать ключ»). По проводу уходит запись: `Settings.llm_api_key` или `clear_api_key`. `GetSettings` возвращает `has_api_key` и пустую строку ключа. В аудит и лог ключ не пишется. В Claim воркера ключ есть, потому что воркер сам ходит в модель.

## Токены демона

Их создаёт `arli-daemon` при старте, если файлов ещё нет. Каталог — `ARLI_STATE_DIR` или `~/.local/share/arli`. Режим `0600`.

| Файл | Кто предъявляет | Зачем |
|---|---|---|
| `ui_token` | оболочка, `arli-probe`, smoke | все RPC `Agent`, кроме Health |
| `internal_token` | только `arli-agent` | открыть `AgentHub.Session` |

Копировать токены на другую машину не нужно: демон новой установки создаст свои. `run-dev.sh` использует отдельный каталог `~/.local/share/arli-dev`, чтобы не мешать установленному демону.

Метаданные: `authorization: Bearer <token>`, сравнение за постоянное время, отказ `UNAUTHENTICATED`.


Session дополнительно требует секрет конкретного запуска worker: daemon генерирует
32 случайных байта через getrandom, передаёт их только в окружении дочернего процесса
ARLI_WORKER_LAUNCH_TOKEN; arli::auth отправляет x-arli-worker-launch. Этот секрет
не сохраняется в файле, БД, UI или логах. Он меняется при respawn и отзывается при
reap/kill. Проверка выполняется до занятия Session, затем Hello.pid должен совпасть
с PID зарегистрированного дочернего процесса. Самостоятельный запуск arli-agent
только с постоянным internal_token больше не открывает Session.

Это привязка к запуску и защита от устаревшего credential; LOCAL_TCP не подтверждает
PID peer. Процесс того же пользователя с правом чтения /proc/<pid>/environ может
прочитать секрет: эта схема не является изоляцией от произвольного процесса с
такими же правами ОС. Инструментам shell окружение worker не наследуется.

## Фильтрация выдачи

`arli::redact` хранит зарегистрированные credentials в памяти процесса: local
bearer/launch tokens, загруженный ключ модели и токены gRPC provider. Старые
значения после ротации сохраняются в памяти до выхода процесса. Daemon и worker
дополнительно используют закрытый `state/redaction.fingerprints`: длина, rolling
индекс и SHA-256 буквального/JSON-escaped значения, без исходного credential.
Фильтр заменяет буквальные
значения и их JSON-escaped форму; это не распознавание произвольных секретов,
base64/других кодировок или смысловых пересказов модели.

Log sink фильтрует component/text, audit — до truncation. Worker фильтрует
результаты инструментов до LLM, TurnEvent и сохраняемые messages; daemon фильтрует relay/journal/replay и каждый
UI reply. Внутренний Claim с ключом модели и authorization metadata не фильтруются:
они нужны для исполнения и не являются UI выдачей. Token stream удерживает
возможный префикс секрета между chunks; незавершённый префикс на границе сообщения
заменяется, что может скрыть совпавший обычный короткий суффикс текста.

Memory registry ограничен 512 представлениями / 1 MiB. Durable ledger ограничен
512 отпечатками / 128 KiB; превышение квоты или повреждение прекращает регистрацию,
а недоступность ledger блокирует событие/продолжение turn и подавляет текст выдачи.
Файлы проверяются по UID, private permissions, regular type и link count, открываются
с O_NOFOLLOW. Межпроцессный flock защищает append, fsync фиксирует запись и создание
файла. Незавершённый append после сбоя означает отказ запуска до восстановления
оператором, а не автоматическое забывание прежних fingerprints. Не удаляйте ledger
при обычной ротации ключа. Прочие процессы с тем же UID не входят в эту границу.

Fingerprint lookup позволяет скрыть старое значение после rotation + restart,
включая сохранённые ранее raw task/title и исходный idempotent retry. Эти данные
не изменяются фильтром UI. Token stream с durable fingerprints удерживает до длины
самого длинного зарегистрированного значения, затем выпускает безопасный текст.
SDK persistence opt-in: `redact::enable_persistence(path)`; daemon/worker включают
его до чтения credentials. Для SHA-256 нужен OpenSSL Crypto (также SDK dependency).

Нельзя восстановить неизвестные прежние ключи, которые были удалены до внедрения
ledger: такие исторические данные не получают ретроактивной гарантии. Произвольные
неизвестные секреты и альтернативные кодировки не распознаются.

Фоновый supervisor читает тот же ledger по пути из доверенного launcher config;
plaintext credentials и окружение worker ему не передаются. Вывод stdout/stderr
проходит общий Stream до записи в output.log / output.log.1. Ротация сохраняет
UTF-8 границы, каждый файл ≤1 MiB. Удерживаемый хвост может задержаться до следующего
вывода или завершения процесса; при forced stop он отбрасывается, чтобы не записать
незавершённый секрет. При ошибке фильтра/записи supervisor убивает и reap-ит свою
дочернюю группу; отсутствие result фиксируется как lost, без выдуманного exit code.
Это не переписывает уже существовавшие логи от старых версий продукта.
